Build a studio from three clear inputs.

Choose the pane layout, then describe each pane with a header, a body, and a footer. The generator supplies the HTML and CSS for each selected type.

1–3 panes 3 region slots per pane Static HTML + CSS output No application bundler
↗

This v4 config-file proposal has been superseded. The v6 design keeps the outside choice to pane count only and uses Handlebars internally for page regions. See the v6 story and command guide for the current direction.

First, what can I run today?

The published package currently accepts a pane count, target folder, and optional title. This command creates a standard three-pane Monaco Studio using the published release:

npx @keshavsoft/monaco-json-studio 3 ./my-json-studio --title="Operations Studio"
!

Version status: the typed header/body/footer work is a local v4 preview in this repository. It has not been published. The published npx package does not yet accept the region configuration shown below.

Proposed v4 command

For the region-aware version, keep the terminal command short and put the understandable choices in one JSON file next to the project:

# Proposed CLI contract — shown for review
npx @keshavsoft/monaco-json-studio --config ./studio.config.json

The config should be the consumer’s one place to declare the title, output folder, and panes. Pane count comes from the number of entries, so it is not repeated in a separate setting.

{
  "title": "Operations Studio",
  "output": "./my-json-studio",
  "panes": [
    {
      "header": { "type": "file-picker", "label": "Instructions" },
      "body":   { "type": "monaco", "language": "json", "file": "./data/instructions.json" },
      "footer": { "type": "cursor" }
    },
    {
      "header": { "type": "file-picker", "label": "Data" },
      "body":   { "type": "monaco", "language": "json", "file": "./data/data.json" },
      "footer": { "type": "note", "text": "Editable source data" }
    },
    {
      "header": { "type": "title", "label": "Output" },
      "body":   { "type": "monaco", "language": "json", "file": "./data/columns.json" },
      "footer": { "type": "none" }
    }
  ]
}
✓

What a consumer needs to learn: choose a region type and provide its options. The generator owns the markup, IDs, CSS classes, and layout details.

Available region types in the preview

The first proof keeps the body as Monaco and varies the header and footer. New body types such as an image or instructions view can be added later behind the same contract.

SlotTypeOptions shown in this draftResult
Headerfile-pickerlabelPane label, file button, and current file name.
HeadertitlelabelCompact title bar with no file control.
Bodymonacolanguage, fileMonaco mount area loaded with the selected starting file.
Footercursor—Live line and column for that pane.
FooternotetextShort pane-specific note.
Footernone—No footer region; the body uses the extra space.

What the command creates

The output is an ordinary folder that can be opened, inspected, and hosted as a static site. The folder contains the generated page, data, and separated stylesheets:

my-json-studio/
├── index.html
├── css/
│   ├── base.css
│   ├── studio.css
│   ├── pane-layout.css
│   └── pane-regions.css
├── data/
└── js/
    ├── index.js
    └── state.js

Run the command

The generator reads the config and writes the requested project folder.

Open the generated page

Serve the folder with any local static server, then open its index.html.

Inspect or extend the result

The output is plain HTML and CSS. The config remains the short, repeatable way to create another variant.

Using the package from a Node project

If the generator is called from automation instead of a terminal, the intended package surface should still stay small: one high-level generateStudio(config) entry point that accepts the same config shape. The HTML-spec assembler and serializer remain implementation details.

// Proposed programmatic usage after the config contract is finalized
import { generateStudio } from '@keshavsoft/monaco-json-studio';

generateStudio({
  title: 'Operations Studio',
  output: './my-json-studio',
  panes: [ /* header, body, footer for each pane */ ]
});

This import signature is part of the proposed consumer contract. The local v4 preview currently exposes lower-level functions and uses a different input shape; the implementation should be simplified before this becomes a published API.
