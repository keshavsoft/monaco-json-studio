A small input · A complete workspace

Say how many panes. The studio builds the rest.

Choose one, two, or three. Monaco JSON Studio composes the shell, the pane layout, and each pane’s header, body, and footer into a ready-to-run static project.

1–3 panesOne public choiceHTML + CSS outputNo config file

The whole command

Run the package with the pane count. It creates a monaco-studio folder in the current directory.

npx monaco-json-studio 3

Use 1 for a single full-width pane, 2 for a side-by-side pair, or 3 for a three-stage workspace. For this local source preview, run node ./bin/index.js 3 from the repository root.

ℹ
Release status: v5 is implemented in this local source tree and has not been published. The command above describes the v5 consumer contract; registry users continue to receive the currently published package until a release is made.

What happens after the number

The count moves through one clear generation story. Each step has a name and a focused responsibility.

01

Choose count

Validate that the request is 1, 2, or 3.

02

Create shell

Build the studio title bar and global status footer.

03

Arrange panes

Set a one, two, or three-column CSS grid.

04

Compose regions

Give each pane its header, Monaco body, and footer.

05

Write project

Serialize HTML and copy CSS, data, and runtime files.

How the source tells that story

The caller sees one operation. Internally, small creators build the studio shell and pane regions, then the document builder joins their output.

Studio-level pieces

createStudioHeader and createStudioFooter build the chrome around the workspace. createWorkspace chooses the grid and asks for the requested panes.

Pane-level pieces

createPane composes createPaneHeader, createPaneBody, and createPaneFooter. Their HTML specs and styles live in the v5 assets folder.

src/v5/
├── generateStudio/       the one high-level operation
├── createStudioDocument/ the complete HTML document
├── createStudioHeader/   global studio header
├── createWorkspace/      grid and pane count
├── createPane/
├── createPaneHeader/
├── createPaneBody/
├── createPaneFooter/
├── createStudioFooter/   global studio footer
├── serializeHtml/
└── internal/             pane defaults and spec helpers

assets/v5/
├── specs/regions/        header, body, and footer markup specs
├── css/                  shell, layout, and region styles
└── templates/            browser-side Monaco controller

The studio header/footer and pane header/footer are separate on purpose: one pair frames the whole application; the other pair belongs to each pane.

The generated project

The generator writes ordinary files that can be served as a static site. The page structure is already present in index.html; CSS arranges and styles it.

monaco-studio/
├── index.html
├── css/
│   ├── base.css
│   ├── studio.css
│   ├── pane-layout.css
│   └── pane-regions.css
├── data/
└── js/
    ├── index.js
    └── state.js

Simple at the edge, organized inside

The command stays stable while the internal header, body, footer, and CSS implementations can evolve. Adding a new internal region style does not add another decision for the person creating a standard studio.
