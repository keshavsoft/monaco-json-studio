Two consumption styles · one generated studio

Choose a count or pass a config object.

The default export preserves the count-based CLI generator. The named v7 npm API accepts a pane configuration object for richer layouts.

Release status: v7 is local source work and has not been published. The count-only default import and npx command remain unchanged. To try the npm object API, run npm run demo:v7 and npm run dev:v7.

Install after release

npm install monaco-json-studio

Count-based default export

import generateStudio from 'monaco-json-studio';

generateStudio(3);

The default export still accepts 1, 2, or 3, preserving the existing CLI behavior. The output is written to ./monaco-studio.

Object-based npm API

import { createStudio } from 'monaco-json-studio';

createStudio({
  title: 'Dataset Review',
  panes: [
    {
      key: 'catalog',
      header: { type: 'select', options: [
        { label: 'Fasteners', value: 'fasteners', content: [{ item: 'Bolt' }] }
      ] },
      body: { type: 'monaco', language: 'json' },
      footer: { type: 'cursor' }
    }
  ]
});

See the v7 npm API guide for supported regions, validations, and runnable variations.

What stays behind the entry point

Internally, v7 uses Handlebars templates to create the global studio header and footer, the workspace grid, and each pane’s header, body, and footer. Those templates and functions can change without exposing DOM IDs to consumers.

For the command-line version and generated directory structure, see the count-based command guide. For the object schema and examples, see the v7 npm API guide.
